# troubleshoot — 不具合報告からのスキル改善と PR 作成

`maintain` は「改善しよう」という能動的な依頼を扱う。このスキルは逆に、**実運用中に何かがおかしかった**
という受動的な報告を起点にする。原因切り分けとチェックリストは `maintain` に従い、
このスキル固有の責務は「証拠の確認」と「専用ブランチでの PR 作成」。

<HARD-GATE>
実行可否をユーザーに確認する前に、診断・修正・PR 作成へ進むことを禁止する。
誤動作を検知した／報告されただけで自動的に走り出さない。スキップが選ばれたら何もせず終える。
</HARD-GATE>

## 前提

- 開始前に `.claude/skills/maintain/SKILL.md` を読む。契約表と変更種別チェックリスト（A〜D）がここでの正
- 「スキルを改善して」のような能動的・網羅的な改善依頼は `maintain`（+ 必要なら `sdd-improver` エージェント）に譲る。
  こちらは「動かしてみたら想定外だった」という具体的な1件の事象が起点
- **プロダクト実装への指摘は `receive-review`、スキル自体の挙動の異常が `troubleshoot`**
  （「PR レビュー対応がうまくいかなかった」= receive-review スキルの挙動が問題ならこちら）

## 手順

0. **実行可否の確認**: 上の HARD-GATE に従い、「troubleshoot を実行するか、スキップするか」を最初に問う
1. **事象の確認（証拠必須）**: 何をしたか・期待した挙動・実際の挙動・関連スキル名/フェーズ/該当する
   state.md やレポートの箇所を確認する。再現できる具体例なしに次へ進まない
   （`maintain` の失敗パターン「ループの空転」＝証拠なしの「たぶんこう直すと良い」を踏襲しない）
2. **原因切り分け**: 該当スキルの SKILL.md と `maintain` の契約表を突き合わせ、単一スキルの欠陥か
   スキル間境界の契約違反かを判定する。境界の契約違反が疑われる場合は `sdd-improver`（監査モード・
   報告のみ）に切り分けを委譲してよい（自己審査を避ける）
3. **修正案の作成**: `maintain` の変更種別チェックリスト（A〜D）に従う。契約表のどれかに触れるなら
   「追随が必要な場所」を同一変更に含める（1ファイルだけ直すのは最頻の欠陥源）
4. **ユーザーに提示・承認**: 診断結果・修正差分・触れるファイル一覧を提示し、適用してよいか確認する。
   無断で適用や PR 作成に進まない
5. **適用と検証**: 承認後に変更を適用し、`maintain`「変更後の必須検証」の全項目
   （`scripts/validate` で `VALIDATE OK`・旧記述の残存 grep・description 変更時の発火シミュレーション）に従う
6. **ブランチ〜PR**:
   - **修正対象リポジトリの同定を最初に行う**。スキルセットはコピー配布されるため、いま触れているのが
     配布物のコピーなら、正本リポジトリのパスをユーザーに確認してそちらで修正・PR する
     （コピー先で PR を作っても上流に届かない）
   - **`fix/skill-<対象スキル名>-<短い説明>` を main（既定ブランチ）から分岐する**。不具合報告は
     SDD 実行中の `feature/*` ブランチ上で起きるのが典型で、そこから切ると未完成の機能差分が PR に混入する
   - 未コミットの作業があれば、元ブランチでコミットするか stash し、troubleshoot 完了後に復帰することを
     ユーザーに確認してから移動する
   - コミット後、push と `gh pr create --base main` の前に必ずユーザーへ最終確認を挟む。
     PR 本文は「事象（証拠）→ 原因 → 修正内容 → 検証結果（validate OK）」の順で書く
   - `gh` が使えない（未認証・remote なし）場合は、ブランチにコミットするところまでで止め、
     PR 作成手順をユーザーに提示して終える
7. **却下時の記録**: 診断の結果スキル側の欠陥ではないと判断した場合は修正せず、
   `docs/maintain-log.md` に `[不具合却下]` を付けて1行追記する（書式の正は `maintain`。
   ファイルが無ければ新規作成する）

## 原則

- 1件の不具合 = 1 PR。ついでの改善を混ぜて発散させない
