# 和文タイポグラフィ — 受け手の環境で崩れない書き方

## 1. 書体名しか保存されない

`.pptx` は書体の名前だけを保存し、書体そのものは埋め込まない（埋め込みは例外）。受け手の環境にその書体が無ければ PowerPoint が黙って代替し、幅と行送りが変わって、はみ出しや改行位置のずれが起きる。和文では、代替先が無いと豆腐（□）になる。

したがって、**受け手の環境に確実にある書体を選ぶ**ことが、見た目の安定の最初の条件になる。

## 2. 推奨する和文書体

| 書体 | Windows | macOS | 備考 |
|---|---|---|---|
| 游ゴシック（Yu Gothic） | 8.1 以降 | 10.9 以降 | 両OSにある。ただし太さの構成が異なる（Windows: Light/Regular/Medium/Bold、macOS: Medium/Bold）。Windows の Regular は細く見えるので本文も Medium 相当か太字を検討 |
| メイリオ（Meiryo） | あり | Office 同梱の場合のみ | Windows 中心の配布に向く。行間が広い |
| ヒラギノ角ゴシック（Hiragino Sans） | 無し | あり | macOS 中心の配布に向く |
| BIZ UDPゴシック | 10 以降 | 無し | 読みやすいが Windows 限定 |
| 游明朝（Yu Mincho） | 8.1 以降 | 10.9 以降 | 明朝が要るときの第一候補 |
| Noto Sans JP / 源ノ角ゴシック | 無し | 無し | 受け手が持っている確証があるか、埋め込むときだけ |

**既定は游ゴシック。** 受け手の環境が Windows と分かっていればメイリオでもよい。Noto を無条件に指定しない。

## 3. latin と ea の両方に指定する

DrawingML は文字種ごとに書体を持つ（`a:latin` = 欧文、`a:ea` = 東アジア、`a:cs` = 複合文字）。`a:latin` だけを設定すると、和文はテーマの既定書体（多くは MS Pゴシックや游ゴシックだが環境依存）に落ちる。

python-pptx の `run.font.name` は `a:latin` しか書かない。和文の run には必ず `a:ea` も書く。

```python
from pptx.oxml.ns import qn
from lxml import etree

def set_font(run, latin="Yu Gothic", ea="Yu Gothic"):
    run.font.name = latin
    rpr = run._r.get_or_add_rPr()
    ea_el = rpr.find(qn("a:ea"))
    if ea_el is None:
        ea_el = etree.SubElement(rpr, qn("a:ea"))
        latin_el = rpr.find(qn("a:latin"))
        if latin_el is not None:
            latin_el.addnext(ea_el)   # 順序: latin → ea → cs
    ea_el.set("typeface", ea)
```

図表（chart）の文字は `chart.font.name` でも `a:latin` しか書かれない。図表の `txPr` にも同様に `a:ea` を追加するか、軸ラベルや凡例が和文にならない構成（数値と英字）にする。

pptxgenjs の `fontFace` も版によって `a:ea` を書かない。生成後に slide XML を開いて `<a:ea typeface=...>` があるか確認し、無ければ後処理で追加する。

## 4. 欧文・数字

- 和文書体で通すのが最も安全。游ゴシックの欧文と数字は十分に読める。
- 数字を目立たせたい（数字ページ、表）なら Arial。等幅性が高く、桁がそろう。
- 欧文書体を混ぜるなら1種類まで。和文1種＋欧文1種が上限。
- 英数字は半角。全角英数字は使わない。
- 数字と単位の間に半角スペースは入れない（「12%」「3か月」）。

## 5. 型スケール（pt）

| 役割 | 講演型 | 資料型 |
|---|---|---|
| 表紙タイトル | 40〜48 | 36〜40 |
| ページタイトル | 28〜32 | 24〜28 |
| 小見出し | 20 | 16 |
| 本文 | 18〜24 | 14〜16 |
| 図表のラベル | 14 | 12 |
| 注記 | 14 | 12 |
| 出典 | — | 10〜11 |

- 本文の下限は講演型 18pt、資料型 14pt。収まらなければ文字を減らす。
- 階層は大きさと太さで作る。書体を増やして作らない。
- 段の差は 1.4〜1.8 倍。24pt の本文に 26pt のタイトルでは階層が見えない。

## 6. 行送りと段落

- 和文の行間は 1.3〜1.5（`line_spacing = 1.4`）。欧文の既定 1.2 では詰まって見える。
- 段落間は行間より広く（`space_after = 6〜10pt`）、行間で段落を分けない。
- 1行の文字数は本文で全角 25〜35 字。幅の広い箱に小さい文字を流すと、視線が戻れない。
- 箇条書きは1項目1行が理想。折り返す項目が1つだけあると、そこだけ間隔が広く見える。全項目を同じ行数にそろえるか、長い項目を削る。
- 禁則（行頭の句読点、行末の始め括弧）は PowerPoint が処理する。python-pptx で手動改行を入れると禁則が壊れるので、`\n` を本文に入れない。
- 両端揃えは使わない。左揃え。中央揃えはタイトルと一文ページだけ。

## 7. 強調

- 太字か色のどちらか一方。両方は使わない。
- 下線は使わない。リンクに見える。
- 和文に斜体は使わない。書体に斜体が無く、機械的に傾けられて崩れる。
- 字間の調整は基本しない。大見出しで −1〜−2% 程度まで。本文で詰めない。

## 8. 記号と句読点

- 句読点は「、」「。」。「，」「．」を混ぜない。
- 括弧は全角「（）」を和文に、半角「()」を英数字の中に。
- 箇条書きの記号は PowerPoint の箇条書き機能で付ける。本文に「・」「•」を直接書かない（二重になる）。
- 「※」は1ページ1つまで。注記は出典行にまとめる。
- 三点リーダーは「…」1文字。「...」を使わない。

## 9. 文字数の予算（箱の幅から）

箱の内側の幅（inch）× 72 ÷ 文字サイズ（pt）で、1行に入る全角文字数の目安が出る。

| 箱の幅 | 14pt | 16pt | 18pt | 24pt | 28pt |
|---|---|---|---|---|---|
| 4.7in（5列） | 24字 | 21字 | 18字 | 14字 | 12字 |
| 7.0in（7列） | 36字 | 31字 | 28字 | 21字 | 18字 |
| 12.1in（全幅） | 62字 | 54字 | 48字 | 36字 | 31字 |

英数字は 0.5 字と数える。この表で行数を見積もり、箱の高さ（行数 × サイズ × 1.4 ÷ 72 inch）を決める。ぎりぎりに設計しない。1行分の余裕を持つ。

## 10. 代替描画のずれを見込む

視覚確認は LibreOffice で行うことが多い。LibreOffice は游ゴシックやメイリオを持たない環境では別の和文書体（Noto Sans CJK、ヒラギノなど）で描画する。幅は概ね同じだが、行送りと欧文部分が変わる。

**描画環境が指定書体を持っているかを先に確かめる。**

```bash
fc-list | grep -i -E "yu gothic|yugothic|meiryo|hiragino" | head
```

- macOS の Microsoft Office は Calibri、Cambria、Aptos、メイリオなどを OS ではなく Office のアプリ内に持つ。PowerPoint では正しく出るが、LibreOffice からは見えず、確認画像は代替書体で描画される。この場合の確認は「本物とは別の書体で通した」ことになるので、納品報告に書く。
- Aptos（2023年以降の Office の既定欧文書体）は指定しない。古い Office に無く、代替も定まらない。
- 本物の書体で確認したいときは、利用者の許可を得てから書体ファイルを `~/Library/Fonts` に置く。勝手に置かない。

- 確認画像で「ぎりぎり収まっている」は、受け手の環境では溢れると考える。1行分の余裕を持つ。
- 確認画像で溢れているものは、受け手の環境でも溢れる可能性が高い。直す。
- 書体の代替が起きたことは、納品時に書く（「游ゴシックを指定。確認は代替書体で実施」）。

## 11. 納品時に書くこと

- 指定した書体と、受け手の環境に無い場合の見え方
- 確認に使った描画環境と代替の有無
- 書体を埋め込んでいない旨（埋め込みは PowerPoint 側の操作）
