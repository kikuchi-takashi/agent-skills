# 生成AIらしさの点検表 — 兆候と、代わりにすること

「生成AIっぽい」と言われる見た目と文章には、決まった兆候がある。ここに挙げるものは、すべて実際の生成物で繰り返し観察されたものである。ロック前の自己点検と、品質確認の両方で使う。

判断規則は1つ: **足したくなったら引く。** 「もう少し見栄えを」と感じたときに置くものは、ほぼ例外なく兆候になる。余白を増やし、要素を1つ減らし、主張を強くする。

## 1. 視覚の兆候

| 兆候 | なぜ生成AIらしいか | 代わりにすること |
|---|---|---|
| タイトル下の短い飾り線 | 内容と無関係に「見出しらしさ」を演出する定型 | 余白で区切る。タイトルの大きさと太さで足りる |
| ページ上端・下端の全幅色帯 | 情報を運ばない帯 | 消す。章名が必要なら12ptの文字で |
| 側面の縦帯、左端の色柱 | 同上 | 消す |
| カード左縁のアクセント帯 | 定型の「カード」装飾 | 淡い面か、見出しの位置だけで区別 |
| 同型の角丸カード3枚 | 内容の数と無関係に3で揃える癖 | 内容の数で列を決める。カードで囲まず余白で分ける |
| アイコン入りの丸＋見出し＋説明の行 | 「機能一覧」の定型 | 表か箇条書きに。アイコンは意味を持つときだけ |
| ベント型グリッド（大小のカードの敷き詰め） | 1枚に多主張 | 1枚1主張に分割 |
| 紫→青のグラデーション、メッシュ、オーロラ | 無指示のときの既定の背景 | 単色。地は白 |
| ガラス風の半透明パネル、光彩、ぼかし | Web の装飾を持ち込んだもの | 使わない。PowerPoint でも崩れる |
| 絵文字、✅🚀✨ などの記号装飾 | 文章の代わりに記号で感情を出す癖 | 消す。強調は太字か色で |
| 毎ページの巨大な数字 | 主張が無いページを数字で埋める | 数字ページは2〜3回まで。数字が主張を支えるときだけ |
| 毎ページ下部の「まとめ帯」「Key Takeaway」 | 主張を本文で言えていない | 結論は結論のページで。本文ページはタイトルが主張 |
| 同じレイアウトの反復 | テンプレに流し込んだだけ | 主役（図・文・数字・表）を回す |
| 全要素が均等に主張する（主役不在） | 「均等に整える」癖 | 1要素を120%、残りを80%に |
| クリーム・ベージュ地に細いセリフ | 無指示のときの「上品」の既定 | 白地。書体は主題から |
| 青の既定、テラコッタの既定 | 無指示のときの色 | 主題から導く |
| 角丸と直角の混在、画像だけ角丸でない | 一貫性の欠如 | 1つの角処理で統一 |
| パレットを飾りとして使う（色帯、虹色の罫線） | 色が内容ではなく装飾に使われている | 色は意味を持つ要素（系列、強調）だけに |
| 文字入りの生成画像 | 文字が崩れる | 画像に文字を入れない。文字はテキストで |
| 全面が画像（スクリーンショット）のページ | 編集できない | ネイティブの図形・表・図に |

**目を細めるテスト**: 描画画像を縮小して見る。3〜4段の階層（主役、タイトル、支える要素、細字）が区別できなければ、階層が無い。主役を大きくし、他を静かにする。

**引き算パス**: 各ページで最も不要な要素を1つ見つけて消す。それで崩れるページは設計されておらず、装飾されていた。

## 2. 文章の兆候（日本語）

### タイトル

| 兆候 | 代わりに |
|---|---|
| 話題ラベル: まとめ、概要、背景、目的、課題、現状、市場概況、今後の展望、ポイント、要点、施策、方針 | 主張の一文 |
| 「〜について」「〜のご紹介」「〜の全体像」「〜のあり方」 | 何が言えるかを書く |
| 「〜の重要性」「〜の可能性」 | 何がどれだけ重要か、何が起きるかを書く |
| 「Key Takeaways」「Next Steps」「Agenda」 | 日本語で、内容を書く |

### 語彙

避ける語と、その語が隠している問い:

| 避ける | 隠している問い |
|---|---|
| シームレス、スムーズ | 何と何の間で、何が省けるのか |
| 革新的、画期的、飛躍的、抜本的、次世代 | 従来と何が違うのか。数値は |
| ソリューション、プラットフォーム、エコシステム | 具体的に何か |
| シナジー、レバレッジ、エンパワー | 誰が何を得るのか |
| 〜を実現、〜を推進、〜を加速、〜を最大化 | いつまでに、どれだけ |
| 〜の鍵、〜が重要、〜が求められる | 誰が、何をするのか |
| 〜に寄与、〜を通じて〜が可能に | 因果の中身は |
| 多様な、様々な、包括的な、効果的な、戦略的な | 具体的に何が |
| 効率化、最適化、高度化（名詞化の連鎖） | 何をどうするのか |
| DX推進、AI活用（中身なし） | 何の業務を、どう変えるのか |

置き換えの例:

- 「シームレスな連携を実現」→「見積から請求まで再入力なしで通る」
- 「効率化を推進し生産性向上に寄与」→「月次締めが5営業日から2営業日になる」
- 「革新的なソリューション」→「在庫を見て自動で発注する仕組み」

### 文体

| 兆候 | 代わりに |
|---|---|
| 三点セットの強制（常に3項目・3列・3ステップ） | 内容の数で書く。2でも4でも5でもよい |
| 「まず〜、次に〜、最後に〜」の反射 | 順序が意味を持つときだけ番号 |
| 「さらに」「また」「加えて」で並べ続ける | 要素を減らす。並列は箇条書きに |
| 両論併記で主張がない（「一方で〜も重要」） | 立場を取る。反論は「前提とリスク」に隔離 |
| 体言止めの連発 | 述語のある文と混ぜる |
| 敬体と常体の混在 | どちらかに統一。スライドは常体が読みやすい |
| 感嘆符、末尾の「！」 | 使わない |
| 「※」の多用 | 注記は1ページ1つ、出典行に |
| 数値・引用・ロゴ・顧客名の捏造 | 裏付けの無い数字は「要確認」と明記 |

**声に出すテスト**: 各行を、その分野の専門家が会議室で口にするか考える。プレスリリースか教科書の要約に聞こえたら書き直す。

## 3. 構造の兆候

| 兆候 | 代わりに |
|---|---|
| 1枚に主張が2つ以上 | 分割 |
| 図はあるが、何を読み取るか書いていない | 読み取りの一文を添える |
| 見るだけで語れない（話者が説明できない）ページ | 削るか主張を足す |
| 密度が全ページ同じ | 緩急をつける |
| 章番号・目次が内容の実態と合わない | 実態が無いなら番号を外す |
| 「ご清聴ありがとうございました」で終わる | 結論・依頼で終わる |
| 出典が無い数字 | 出典行かノートに書く |

## 4. 許されるもの（過剰な修正を防ぐ）

- 表の見出し行の下の罫線1本（構造を運んでいる）
- フッターの罫線1本（全ページ同じ位置）
- 強調色1色を、主張を支える要素に使うこと
- 主張が数字そのものであるときの大きな数字
- 内容の数が本当に3のときの3列比較
- 章扉の一色面（3回まで）
- 主題由来の図版（路線図、計器、罫線）を繰り返すこと。これはシグネチャであって装飾ではない

判断に迷ったら、その要素を消して意味が減るかを見る。減らなければ装飾である。
