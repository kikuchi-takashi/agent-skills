# pptx-create — 生成AIらしさを消し、設計を安定させて作る

## 原則

1. **内容が先、装飾は後。** スライドは主張と証拠の器で、飾りは情報を運ばない限り置かない。
2. **デザインは主題から導く。** 別の主題を流し込んでも成立する見た目は、まだ設計されていない。
3. **足したくなったら引く。** 「見栄えを良くしたい」衝動は、余白を増やし要素を減らす方向に使う。
4. **合格は機械の出力と描画画像で示す。** 「問題ないはず」という口頭宣言は合格ではない。
5. **システムは固定し、主役だけ変える。** 色・書体・グリッドは全ページ同じ、図・数字・表・文の主役はページごとに変える。

## 工程

作業ファイルは出力先の `deck/` 配下（`brief.md`、`outline.md`、`design-lock.md`、`design-lock.json`、`build.py`、`qa/`）に置く。各工程の産出物が無いまま次に進まない。

### 1. ブリーフ（`deck/brief.md`）

聴衆（役職・前提知識・抵抗）、目的（聴衆が終了後にどう変わるか）、場面（**講演型**: 話者が語る／**資料型**: 読んで完結）、持ち時間、枚数、ブランド制約（テンプレ・ロゴ・指定色）、素材、言語を確認する。足りない項目だけ聞く。「任せる」と言われたら仮定を書いて進み、納品時に列挙する。

**既存テンプレ（.pptx/.potx）を渡された場合は、それがデザインロックになる。** 工程3で新しい配色や書体を作らず、テンプレから抽出する。

### 2. 構成（`deck/outline.md`）

`references/storyline.md` に従い、1枚ごとに「主張を一文で書いたタイトル」「役割」「証拠と出典」「展示物（図・表・数字・文）」「密度」を書く。書いたらタイトルだけを順に読み、それだけで論旨が通るか確認する（ゴーストデッキテスト）。通らなければ生成に進まない。

10枚を超える、または内容が複雑なら、この段階で利用者に構成を見せて確認を取る。

### 3. デザインロック（`deck/design-lock.md` と `deck/design-lock.json`）

`references/design-lock.md` の雛形で、パレット・書体・型スケール・グリッド・シグネチャ・レイアウト名簿を確定する。書体の選び方は `references/typography-ja.md`、レイアウトは `references/layout-catalog.md`。ロック前に `references/anti-ai-checklist.md` の視覚項目で自分の案を点検する。

8枚を超えるデッキでは、表紙と本文1枚だけを先に生成・描画して利用者に見せ、方向を確定してから全ページを作る。ブランド制約が無く方向が定まらないときは、主題から導いた案を2つ（それぞれ表紙＋本文1枚）並べて選んでもらう。3つ以上は出さない。

### 4. 生成（`deck/build.py`）

`references/engine-notes.md` の骨格に従い、1本の python-pptx スクリプトで全ページを生成する。座標・色・サイズはすべてロックの定数から導き、スクリプト内に直値を散らさない。積む・並べる・下端に置くは骨格のヘルパー（`vstack`、`spread`、`content_band`、`bottom_note`）で計算し、手で y を置かない。図表は原則ネイティブ（`add_chart`、`add_table`）で作り、画像化しない。発表者ノートに話す内容と出典を入れる。

実行環境に追加インストールやネットワークが無いことがある。必要なライブラリが無ければ、純 Python のものは同梱して `sys.path` に加える（`references/engine-notes.md` 1 節）。1回の実行に時間の上限がある環境では、生成と描画を数枚ずつに分ける。

### 5. 品質確認（`deck/qa/`）

`references/qa.md` の3ゲート（内容・ファイル・視覚）を通す。描画は pptx-review 同梱の `render_preview.py`（Pillow のみ）で行う。**pptx-review スキルが導入済みなら、別コンテキスト（サブエージェント）で監査させる。** 無ければ `references/qa.md` のチェックリストと描画画像で自分で行うが、生成直後の自分の目は甘いので、全ページを新鮮な目で見直す。

修正したら変更したページだけ再描画し、新しい指摘が出なくなるまで回す。3周して収束しなければ、残った問題を利用者に報告して判断を仰ぐ。

### 6. 納品

- `.pptx`（編集可能）
- 構成の概要（各ページのタイトル一覧）
- 置いた仮定、未確認の数値、書体の依存（受け手の環境に無い可能性）
- 品質確認の証拠（lint の要約、描画画像の場所）

## 絶対規則

- タイトル下の飾り線、上下の色帯、側面の縦帯、カード左縁の帯、絵文字を置かない（`references/anti-ai-checklist.md`）。
- タイトルは話題ラベル（「まとめ」「市場概況」）ではなく主張の一文にする。
- 1枚に主張は1つ、展示物も原則1つ。
- 本文の最小サイズは講演型 18pt、資料型 14pt。収まらなければ文字を減らすか分割する。縮小しない。
- 数値・引用・ロゴ・顧客名を捏造しない。裏付けのない数字は「要確認」と明記する。
- 和文の run には latin と ea の両方に同じ書体を指定する。
- 既存ファイルを上書きしない。別名で保存する。
- lint の JSON と描画画像を確認せずに「完成」と言わない。

## 短縮経路

5枚以下で図表がなく、利用者が急いでいる場合は、工程2と3を `deck/outline.md` 1本にまとめてよい。工程5の品質確認は省略できない。

## 出力

編集可能な `.pptx` と、構成概要、仮定と未解決事項、品質確認の証拠を返す。
