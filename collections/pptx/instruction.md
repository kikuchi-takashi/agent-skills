# サンプル: 営業資料向けの束ね方

**これは配布スキルではなく、このコレクションを特定の用途に束ねる例です。** 自分の用途（採用、社内報告、研究発表など）に合わせて写して直してください。

このサンプルが足しているのは、営業という用途に固有の3つだけです。

1. 要件の聞き方（商談のゴール、決裁者、利用シーン）
2. ストーリーラインの型（提案書、製品紹介、会社紹介、事例、ピッチ）
3. 営業固有の規則（顧客視点、捏造の禁止、競合比較の扱い）

配色の具体値と署名の例も置いていますが、**どちらも出発点であって既定値ではありません。** 商材と相手に合わせて毎回選び直します。

**それ以外はコレクションのスキルに任せます。** 設計の原則は `pptx-design`、レイアウト原型・生成の骨格・検査・納品報告は `pptx-create` を読んで使ってください。書き写さないでください。書き写すと、コレクション側の改善が反映されなくなり、値がずれます。

前提: `pptx-design` / `pptx-create` / `pptx-edit` / `pptx-review` が導入済みであること（`pptx-suite` として一体で入ります）。

### どの工程を、どのスキルが持つか

このサンプルの節番号は、下のスキルの工程に対応します。**新規作成は `pptx-create` を起点にし、ロックが要る段で `pptx-design` に渡します。**

| この文書 | 実体 |
|---|---|
| 0. 能力の確認 | `pptx-create` 工程0（`pptx-design` を単体で使うならその工程0） |
| 1. 要件整理 | `pptx-create` 工程1（ブリーフ） |
| 2. ストーリーライン | `pptx-create` 工程2（構成） |
| 3. デザインロック | **`pptx-design`**（`pptx-create` 工程3はその受け取り） |
| 4. 生成 | `pptx-create` 工程4 |
| 5. 品質確認 | `pptx-create` 工程5（4ゲート）／`pptx-review` |
| 6. 納品報告 | `pptx-create` 工程6 |

既存の営業資料を直す依頼は、この流れではなく `pptx-edit` に入ります。

---

## 0. 能力の確認

`pptx-create` の工程0に従います。使えるライブラリと描画手段を確かめ、経路を決め、確認した版を控えます。**足りないライブラリを勝手に導入しません。** 無いときにどう縮退するかは各スキルの工程0の表にあります。

## 1. 要件整理（営業固有）

`pptx-create` の工程1（ブリーフ）に、次の項目を足して埋めます。判断できない項目は仮定を置いて進め、納品時に明示します。

| 項目 | 例 |
|---|---|
| 資料の種類 | 提案書 / 製品紹介 / 会社紹介 / 事例紹介 / 商談フォロー / ピッチ |
| 商材 | 何を、誰に、いくらで |
| 想定読者 | 業種・役職・決裁権の有無・技術リテラシー |
| 商談のゴール | 次回アポ / PoC 合意 / 見積提示 / 稟議通過 / 契約 |
| 利用シーン | 対面投影・オンライン共有（**講演型**） / 事前送付（**資料型**） |
| ブランド | ロゴ・コーポレートカラー・指定フォントの有無 |
| 既存資料 | 流用すべきスライド・数字・事例 |
| デザイン水準 | 標準 / 高度（社外の重要提案・ピッチは高度） |

利用シーンは、そのまま骨格の `MODE`（`talk` / `doc`）と lint の `--mode` になります。**利用シーンとデザイン水準はここで決め、3節で `pptx-design` に渡します**（`pptx-design` 側で決め直しません）。

既存の営業資料に足す依頼なら、ここで `pptx-edit` に移ります。設計値は目分量で読まず、`pptx-review` の `extract_style.py` で実測してロックにし、複製元から作ります。

## 2. ストーリーライン（営業固有の型）

`pptx-create` の工程2で構成を書くとき、下の型を出発点にします。タイトルは必ず主張文にします（「導入効果」ではなく「導入3か月で問い合わせ対応時間を40%削減」）。

**提案書（12〜14枚）**
表紙 → 本日お伝えしたいこと（結論3点） → 御社を取り巻く変化 → 直面している課題 → 放置した場合のコスト → 解決の方向性 → ご提案の全体像 → 主要な内容（3〜4点） → 導入効果 → 導入事例 → 料金 → スケジュールと体制 → 想定される懸念への回答 → 次のステップ

**製品・サービス紹介（8〜12枚）**
表紙 → 一言で言うと → 解決する課題 → 特長3点 → 仕組み・画面 → 導入効果 → 事例 → 料金 → 導入の流れ → お問い合わせ

**会社紹介（8〜10枚）**
表紙 → ミッション → 会社概要 → 事業領域 → 強み3点 → 実績 → 事例 → 体制 → 沿革 → お問い合わせ

**事例紹介（5〜7枚）**
表紙 → 顧客プロフィール → 導入前の課題 → 導入内容 → 成果（数字） → 担当者の声 → 次のアクション

**ピッチ（10枚前後）**
表紙 → 課題 → 解決策 → プロダクト → 市場規模 → ビジネスモデル → トラクション → 競合優位 → チーム → 依頼事項

### 型とレイアウト原型の対応

内容の役割に合う原型を選びます（`pptx-create` の `layout-catalog.md` と骨格の `skeleton()`）。同じ原型を3枚以上続けません。**下の表は照合表ではなく出発点です。** 各ページで候補を2つ以上出し、決め手を書いてから選びます（`pptx-design` の `design-principles.md` 7節）。

| 内容 | 原型 |
|---|---|
| 結論3点、次のステップ | `closing`、`steps` |
| 課題、放置コスト | `claim-evidence`（図表つき） |
| 効果、実績の数字 | `hero-number` |
| 料金、比較 | `comparison`、`table` |
| 前提と本体を分ける | `split-asymmetric` |
| 話の転換 | `statement` |
| 章の区切り（12枚超のとき） | `divider` |

## 3. デザインロック（営業向けの出発点）

`pptx-design` で `design-lock.json` と `design-lock.md` を書きます。ブランド指定があればそれがロックです（新しい配色を作らず、`extract_style.py` で実測して写します）。無いときの出発点として、次を使えます。**出発点であって既定値ではありません。** 商材と相手の業種に合わせて調整してください。

```json
{
  "fonts": ["Yu Gothic", "Meiryo"],
  "palette_basis": "商談で使う自社ブランドの濃紺。強調色は見積効果の数字だけに使う",
  "palette": {
    "bg": "FFFFFF",
    "text": "1A1A1A",
    "muted": "5C5C5C",
    "line": "D9D9D6",
    "panel": "F4F4F2",
    "primary": "1F2A44",
    "accent": "E86A1F"
  },
  "chart_series": ["1F2A44", "E86A1F", "5C5C5C", "D9D9D6"],
  "mode": "talk",
  "min_font_pt": 14,
  "allow": [
    {"code": "PLACEHOLDER_TEXT", "reason": "【要確認】は納品時に一覧で報告する意図的な印。埋めたら外す"}
  ]
}
```

`mode` は1節の利用シーンをそのまま入れます（`talk` なら `min_font_pt` は 14、`doc` なら 12）。高度デザインなら7色を手で選ばず、`pptx-design` の `generate_palette.py` に基準色を渡して3候補から選びます。

`allow` の登録は、**納品報告で一覧にすることとセット**です。埋め終わったらこの行を外し、lint を通し直します。

役割は、地が白、本文が `1A1A1A`、補助が `5C5C5C`、罫線と淡い面が `D9D9D6` と `F4F4F2`、主色が濃紺 `1F2A44`、強調がオレンジ `E86A1F` です。これは営業資料用の出発点であり、生成骨格へ固定された既定値ではありません。強調色は1ページ1か所、結論の数字にだけ使います。

グリッドと型スケールは骨格の既定をそのまま使います（自分で決め直さない）。書体は受け手の環境に合わせます（`pptx-design` の `typography-ja.md`）。

### 署名は商材から作る

営業資料はテンプレートに見えた瞬間に読まれなくなります。**禁止事項を守るだけでは「無難だが誰が作っても同じ」になります。** `pptx-design` の 4条件（主題由来／1つの形に1つの意味／初出で凡例／3層で出す）で、商材の世界から印を1つ作ります。

- 物流なら伝票の罫線と等幅の番号、SaaS なら画面の枠と状態の記号、製造なら図面の寸法線、金融なら台帳の締め線
- **その印を別の商材の提案書に移せてしまうなら、まだ商材から作られていません**
- 初出のページに一行の凡例を置きます（骨格の `motif_legend()`）。凡例が無い見慣れない形は、ただの飾りに見えます
- 強く出すのは3回まで（表紙・章扉・結び）

**置いてはいけないもの。** 営業資料でとくに出やすい定型です。

- ページ上端・下端の全幅の色帯（`COLOR_BAND`）
- タイトル下の飾り線を全ページに繰り返す（`DECORATION_REPEATED`）
- 同型の丸角カード3枚、アイコン入りの丸＋見出しの定型行
- 毎ページ下部の「まとめ帯」

いずれも lint が咎めます。区切りは余白とタイトルの大きさで足ります。

## 4. 生成

`pptx-create` の工程4に従い、design-lock.json を入力に取って骨格のレイアウト関数を呼びます。営業固有で足りない部品があれば、骨格の `skeleton()` と `split()` / `emphasis()` / `vstack()` から組み立てます（座標を手で置かない）。横並びは `emphasis(n, hero)` で主役を決めてから作り、等分（`spread()`）は項目が本当に等価なときだけにします。

**箱の高さも手で置きません。** 動かせる箱は `place()`、動かせない升目は `fit_text()` を使います。文言が1行増えたときにだけ崩れるのを防ぐためで、営業資料は文言の差し替えが多いぶん効きます。

素材（既存資料、ロゴ、画面写真）は利用者からもらいます。**置く前に正規化します**（`pptx-create` の `materials.md`）。営業資料でよく起きるのは次の3つです。

- スマホで撮った現場写真が横倒しで入る（EXIF の回転を python-pptx が見ない）
- 画面キャプチャの DPI で置かれる寸法が変わる。`add_picture` を直に呼ばず、骨格の `picture()` を使う
- ロゴが SVG でしか無い。**変換せず PNG を利用者に求めます**（変換すると編集できない画像になります）

図表と表は**ネイティブ**で作ります（`add_chart` / `add_table`）。料金表や効果のグラフを画像で貼らないでください。受け手が数字を確認できず、編集もできません。

無い箇所は薄い面に `【要確認：〇〇】` と書いたプレースホルダを置き、納品時に一覧で報告します。

効果や実績の**大きな数字は `fit_size()` でサイズを決めます**。「1,200万円」のように長い数字は上限の 84pt では収まりません。

## 5. 品質確認

`pptx-create` の工程5（4ゲート）をそのまま通します。`--mode` は工程1で決めた利用シーンに合わせます。加えて、営業固有の観点を確認します。

- タイトルだけを順に読んで、商談の筋が通るか
- 主語が「御社」「お客様」になっているか（自社の機能自慢になっていないか）
- 効果・実績の数字に出典があるか。無いものが `【要確認】` になっているか
- 競合比較が事実ベースで、断定的な優劣を書いていないか
- 最終ページが具体的な次の行動と期日で終わっているか
- 表記のゆれ（御社／貴社、全角半角）が無いか

ゲート4（設計）は営業資料でとくに飛ばされがちです。**署名があるか、各ページで形式を選んだ跡（候補と決め手）があるか、横並びの主役が決まっているか**の3つを見ます。`pptx-review` を別コンテキストで走らせると、書いた本人の甘さが入りません。

## 6. 納品報告

`pptx-create` の工程6の項目に、営業固有の1項目を足します。

- **`【要確認】` の一覧と、埋めるために必要な情報**

---

## 営業固有の禁止事項

- 顧客名・実績数字・導入事例・料金・担当者名を推測で埋めない
- 競合他社の欠点を断定的に書かない（事実と出典がある場合のみ、控えめに）
- 依頼された範囲を勝手に広げない（提案書を頼まれて会社紹介を足さない）。有益と思うなら納品報告の末尾で提案する

## 追加情報が無いときの既定

- 資料の種類: 提案書
- 枚数: 12枚
- 利用シーン: 対面投影（`talk`）。後日送付もあるなら脚注で補う
- デザイン水準: 標準（社外の重要提案・ピッチなら高度）
- 配色: 上の出発点（濃紺＋オレンジ）。**`palette_basis` は毎回書きます**——空だと骨格が例外で止まります
- 出力先: `./output/`。作業ファイル（`brief.md`、`outline.md`、`design-lock.json`、`build.py`、`qa/`）はその下の `deck/` に置きます
