# サンプル: 営業資料向けの束ね方

**配布スキルではなく、コレクションを特定用途に束ねる例です。** 自分の用途に写して直してください。

営業固有として足しているのは3つだけ——要件の聞き方、ストーリーラインの型、営業固有の規則。**それ以外はスキルに任せます**（設計の原則は `pptx-design`、原型・骨格・検査は `pptx-create`）。書き写すとコレクション側の改善が反映されません。ここに置いた配色と署名の例も**出発点であって既定値ではありません**。

前提: `pptx-suite`（`pptx-design` / `pptx-create` / `pptx-edit` / `pptx-review`）が導入済み。

**新規作成は `pptx-create` を起点に**し、3節で `pptx-design` に渡します。下の節番号は `pptx-create` の工程に対応し、3節だけ `pptx-design` が実体です。既存資料の修正はこの流れではなく `pptx-edit` に入ります。

## 0. 能力の確認

`pptx-create` の工程0。使えるライブラリと描画手段を確かめ、版を控えます。**足りないものを勝手に導入しません**（縮退の仕方は工程0の表）。

## 1. 要件整理

工程1（ブリーフ）に次を足します。判断できない項目は仮定を置き、納品時に明示します。

| 項目 | 例 |
|---|---|
| 資料の種類 | 提案書 / 製品紹介 / 会社紹介 / 事例 / 商談フォロー / ピッチ |
| 商材 | 何を、誰に、いくらで |
| 想定読者 | 業種・役職・決裁権・技術リテラシー |
| 商談のゴール | 次回アポ / PoC 合意 / 見積提示 / 稟議通過 / 契約 |
| 利用シーン | 対面投影・オンライン（**講演型**） / 事前送付（**資料型**） |
| デザイン水準 | 標準 / 高度（社外の重要提案・ピッチは高度） |
| ブランド | ロゴ・指定色・指定書体の有無 |
| 既存資料 | 流用するスライド・数字・事例 |

利用シーンは骨格の `MODE`（`talk`/`doc`）と lint の `--mode` になります。**利用シーンと水準はここで決めて3節に渡します**（`pptx-design` 側で決め直さない）。既存資料に足す依頼はここで `pptx-edit` へ。設計値は目分量で読まず `extract_style.py` で実測します。

## 2. ストーリーライン

工程2で構成を書くときの出発点。タイトルは必ず主張文にします（「導入効果」ではなく「導入3か月で対応時間を40%削減」）。

- **提案書（12〜14枚）** 表紙 / 結論3点 / 御社を取り巻く変化 / 課題 / 放置コスト / 解決の方向性 / 提案の全体像 / 主要な内容 / 効果 / 事例 / 料金 / 体制と日程 / 懸念への回答 / 次のステップ
- **製品紹介（8〜12枚）** 表紙 / 一言で言うと / 解決する課題 / 特長3点 / 仕組み・画面 / 効果 / 事例 / 料金 / 導入の流れ / 問い合わせ
- **会社紹介（8〜10枚）** 表紙 / ミッション / 会社概要 / 事業領域 / 強み3点 / 実績 / 事例 / 体制 / 沿革 / 問い合わせ
- **事例（5〜7枚）** 表紙 / 顧客プロフィール / 導入前の課題 / 導入内容 / 成果の数字 / 担当者の声 / 次のアクション
- **ピッチ（10枚前後）** 表紙 / 課題 / 解決策 / プロダクト / 市場規模 / 収益モデル / トラクション / 競合優位 / チーム / 依頼事項

原型は内容の役割で選びます（`pptx-create` の `layout-catalog.md`）。同じ原型を3枚以上続けません。**下は照合表ではなく出発点で、各ページ候補を2つ以上出して決め手を書いてから選びます**（`pptx-design` の `design-principles.md` 7節）。

結論3点・次のステップ→`closing`/`steps`、課題・放置コスト→`claim-evidence`、効果の数字→`hero-number`、料金・比較→`comparison`/`table`、前提と本体→`split-asymmetric`、話の転換→`statement`、章の区切り→`divider`。

## 3. デザインロック（`pptx-design`）

ブランド指定があればそれがロックです（新色を作らず実測して写す）。無いときの出発点:

```json
{
  "fonts": ["Yu Gothic", "Meiryo"],
  "palette_basis": "商談で使う自社ブランドの濃紺。強調色は効果の数字だけに使う",
  "palette": {"bg": "FFFFFF", "text": "1A1A1A", "muted": "5C5C5C", "line": "D9D9D6",
              "panel": "F4F4F2", "primary": "1F2A44", "accent": "E86A1F"},
  "chart_series": ["1F2A44", "E86A1F", "5C5C5C", "D9D9D6"],
  "mode": "talk", "min_font_pt": 14,
  "allow": [{"code": "PLACEHOLDER_TEXT", "reason": "【要確認】は納品時に一覧で報告する印。埋めたら外す"}]
}
```

`mode` は1節の利用シーン（`talk` なら `min_font_pt` 14、`doc` なら 12）。`allow` の登録は納品報告での一覧とセットで、埋めたら外して lint を通し直します。高度デザインでは7色を手で選ばず `generate_palette.py` に基準色を渡し、3候補から選びます。強調色は1ページ1か所、結論の数字にだけ。グリッドと型スケールは骨格の既定のままにします。

**署名は商材から作る。** 禁止を守るだけでは「無難だが誰が作っても同じ」になります。物流なら伝票の罫線と等幅の番号、SaaS なら画面の枠と状態の記号、製造なら図面の寸法線。**別の商材の提案書に移せてしまうなら商材から作られていません。** 初出のページに一行の凡例を置き（`motif_legend()`）、強く出すのは3回まで。

**置かないもの**（lint が咎めます）: 上下の全幅色帯、全ページのタイトル下飾り線、同型の丸角カード3枚、アイコン入りの丸＋見出しの定型行、毎ページの「まとめ帯」。区切りは余白とタイトルの大きさで足ります。

## 4. 生成

工程4に従い、`design-lock.json` を入力に骨格のレイアウト関数を呼びます。座標も高さも手で置きません——縦積みは `vstack()`、非対称は `split()`、横並びは `emphasis(n, hero)` で主役を決めてから（等分 `spread()` は本当に等価なときだけ）、動かせる箱は `place()`、動かせない升目は `fit_text()`。営業資料は文言差し替えが多く、高さを決め打つと1行増えたときだけ崩れます。大きな数字は `fit_size()`（「1,200万円」は 84pt では収まりません）。

素材は利用者からもらい、**置く前に正規化します**（`materials.md`）。営業資料で実際に起きるのは、現場写真が横倒しで入る（EXIF の回転）、画面キャプチャの DPI で寸法が変わる（`add_picture` を直に呼ばず `picture()` を使う）、ロゴが SVG しか無い（変換せず PNG を求める）の3つです。

図表と表は**ネイティブ**（`add_chart` / `add_table`）。料金表や効果のグラフを画像で貼ると、受け手が数字を確認できず編集もできません。素材が無い箇所は `【要確認：〇〇】` を置き、納品時に一覧で報告します。

## 5. 品質確認

工程5の形式的QAとデザイン的QAを分けて通します（`--mode` は1節の利用シーン）。事前にスライド実装仕様書を作り、生成後に設計〜実装対応表を作ります。全ページの個別表示と一覧表示の証跡を残したうえで、営業固有に:

- タイトルだけを順に読んで商談の筋が通るか
- 主語が「御社」「お客様」か（自社の機能自慢になっていないか）
- 数字に出典があるか。無いものが `【要確認】` か
- 競合比較が事実ベースで、断定的な優劣を書いていないか
- 最終ページが具体的な次の行動と期日で終わっているか
- 表記のゆれ（御社／貴社、全角半角）が無いか

**デザイン的QAのゲート4（設計）を飛ばさない**——署名があるか、形式を選んだ跡があるか、横並びの主役が決まっているか。`pptx-review` を別コンテキストで走らせると自分の甘さが入りません。

## 6. 納品報告

工程6の項目に **`【要確認】` の一覧と、埋めるために必要な情報** を足します。

## 営業固有の禁止事項

- 顧客名・実績数字・導入事例・料金・担当者名を推測で埋めない
- 競合他社の欠点を断定的に書かない（事実と出典がある場合のみ控えめに）
- 依頼範囲を勝手に広げない（提案書を頼まれて会社紹介を足さない）。有益なら納品報告の末尾で提案する

## 追加情報が無いときの既定

資料の種類=提案書、枚数=12枚、利用シーン=対面投影（`talk`）、デザイン水準=標準、配色=上の出発点。**`palette_basis` は毎回書きます**（空だと骨格が例外で止まります）。出力先は `./output/`、作業ファイル（`brief.md`、`outline.md`、`design-lock.json`、`build.py`、`qa/`）はその下の `deck/`。
