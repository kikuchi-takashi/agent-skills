# pptx-design — デザイン方針を主題から導き、ロックとして固定する

`pptx-design`、`pptx-create`、`pptx-edit`、`pptx-review` は `pptx-suite` として一体配布する。既存デッキからの設計値抽出では、同じインストール先にある `pptx-review/scripts/extract_style.py` を使う。4スキルの一部だけを配布・導入しない。

**このスキルの成果物は `deck/design-lock.json` と `deck/design-lock.md` の2つ。** 前者は生成骨格と lint が機械的に読む値、後者は人が読む根拠と署名の定義である。他の3スキルはこれを入力に取る——`pptx-create` は骨格の色・書体・型スケールとして読み、`pptx-edit` は既存デッキから同じ形を起こして編集の枠にし、`pptx-review` は `--lock` で監査の基準にする。

## 原則

1. **デザインは主題から導く。** 別の主題を流し込んでも成立する見た目は、まだ設計されていない。パレットも署名も、この主題でなければならない理由を1行で書けること。
2. **静かな層は繰り返し、うるさい層は変える。** 色・書体・余白・タイトル位置は全ページ同じ。レイアウト・主役・密度はページごとに変える。ロックが固定するのは静かな層だけで、うるさい層まで固定すると単調になる。
3. **型は「照合」ではなく「選択」で決める。** 内容の形を先に言葉にし、候補を2〜3出してから選ぶ。最初に当てはまった形をそのまま採らない。
4. **既製の装飾は署名ではない。** 色帯・飾り線・アイコン入りの丸・角丸カードの反復を選ぶのはロックではない。
5. **決めた値には根拠を書く。** `palette_basis` が空のロックは骨格が受け付けない。

設計の考え方は `references/design-principles.md`、避けるものは `references/anti-ai-checklist.md`。**両方を読む。** 禁止だけを守ると、無難だが設計されていないデッキになる。

## 工程

### 0. 能力と入力の確認

`generate_palette.py` の派生色・コントラスト計算は標準ライブラリだけで動くが、**比較用PPTXの書き出しと、既存デザインの抽出には `python-pptx` が要る**。着手時に確かめる。

```python
import importlib

for name in ("pptx", "lxml"):
    try:
        m = importlib.import_module(name)
        print("%-12s %s" % (name, getattr(m, "__version__", "available")))
    except ImportError:
        print("%-12s unavailable" % name)
```

`python-pptx` が無い場合、パレットの候補生成は行えるが比較用PPTXを描けない。色の値だけを示し、見比べは生成後（`pptx-create` の描画確認）に回すと利用者に伝える。既存テンプレからの抽出（工程4）は行えないので、その時点で伝える。確認した版は報告に残す。

| 渡されたもの | 進み方 |
|---|---|
| 既存テンプレ（`.potx`/`.pptx`）や既存デッキ | **それがロックである。** 新しい配色や書体を作らず、工程4で実測して写す |
| ブランドの指定色・書体 | それを基準色として工程2に入る。指定外の色を足さない |
| 主題と場面だけ | 工程1から順に導く |

**デザイン水準（標準／高度）と密度モード（講演型／資料型）は、ブリーフで決まっていればそれを受け取る。** `pptx-create` の工程1で聴衆・目的・場面と一緒に決まる項目なので、ここで決め直さない。ブリーフが無い（このスキルを単体で呼ばれた）ときだけ、主題と場面を聞いてここで決める。

- **水準**: 利用者が高度・印象的・ブランド性のあるデザインを求めた場合、または社外発表や重要提案では高度。高度では工程2でパレットを自動生成する
- **密度モード**: 型スケールが変わり、`pptx-create` の骨格の `MODE` と lint の `--mode` に同じ値が渡る。決めた値を `design-lock.json` の `mode` に書く

### 1. 方向（主題から）

`references/design-principles.md` の1〜5節（主題から導く、不均等に投資する、リズム、層の分離、シグネチャ）を読み、このデッキの方向を決める。次の3つを一文ずつ書けるまで先に進まない。

- **この主題の何が色になるのか**（`palette_basis` に入る文）
- **どのページが最も重いのか**（不均等な投資の対象）
- **署名になりうる形は何か**（工程3で確定する）

### 2. パレット（役割つき7色）

`design-lock.json` の `palette` は `bg`、`text`、`muted`、`line`、`panel`、`primary`、`accent` の**役割名つき**で書く。骨格はこの値を直接読むので、色を骨格へ直書きしない。

**高度デザインでは `references/palette-automation.md` を読み、`scripts/generate_palette.py` を使う。** 主題・ブランド・参考画像から基準色を1つ定め、3候補と比較用PPTXを自動生成し、描画確認した候補をロックへ固定する。派生色・コントラスト調整・候補比較をスクリプトに任せ、7色を手で選ばない。

既存テンプレがある場合は自動生成せず、その配色を抽出して使う（工程4）。

検査（自動生成なら `checks` に出る）:

| 検査 | 下限 |
|---|---|
| `text` と `bg` のコントラスト | 4.5 |
| `muted` と `bg` のコントラスト | 4.5 |
| `primary` / `accent` と `bg` のコントラスト | 3.0 |
| 候補間の色覚距離 | 45 |

`chart_series` も決める（既定は `primary` / `accent` / `muted` / `line`）。系列が5つ以上要るなら、そこで色を足すのではなく図表を分ける。

### 3. 書体・型スケール・グリッド・署名

- **書体**は `references/typography-ja.md`。和文の run には latin と ea の両方に同じ書体を指定する前提でロックに書く。受け手の環境に無い書体は代替に置き換わるので、代替候補まで書く。
- **型スケール**は `references/design-lock-guide.md` の雛形。講演型と資料型で値が違う。`pptx-create` の骨格の `SCALE` と一致させる。
- **グリッド**（キャンバス、余白、列、要素間の最小間隔）も同じく骨格の定数と一致させる。
- **シグネチャは主題から作る。** 4条件（主題由来／1つの形に1つの意味／初出で凡例／静かな標識・幾何そのものの1枚・凡例の3層）を `design-lock.md` に書き切る。書けないなら、まだ署名が無い。うるさい登場は3回まで。
  引き出しとして `scripts/suggest_motif.py` に主題を渡すと候補が出る（`python3 <skills>/pptx-design/scripts/suggest_motif.py "主題の文"`）。**候補は出発点であって既定値ではない。** 一致が弱ければ何も出さないので、そのときは主題から自分で作る。採用するには「この主題でこの形が意味を持つ理由」を1行書く。
- **レイアウト名簿**: このデッキで使う原型を挙げる。原型の一覧と意味は `pptx-create` の `references/layout-catalog.md`。

書き終えたら `references/anti-ai-checklist.md` の**視覚の兆候**で点検する。ロックの段階で兆候を持っているなら、生成しても消えない。

### 4. 既存デザインを写す場合

目分量で読み取らない。`pptx-review` の抽出スクリプトを使う。

```python
import subprocess, sys
subprocess.run([sys.executable, "<skills>/pptx-review/scripts/extract_style.py", "template.potx",
                "--json-out", "deck/design-lock.json", "--md-out", "deck/design-lock.md"], check=True)
```

タイトルの位置・サイズ・色、本文の左端とサイズの語彙、出典の位置、余白、書体、色、行間、そして役割ごとの**複製元**が出る。手順の詳細は `references/design-lock-guide.md` 7節。

抽出したロックは、そのまま `pptx-create`（新規ページ）と `pptx-edit`（既存の編集）の両方の枠になる。既存デッキにページを足す作業自体は `pptx-edit` の担当。

### 5. 確定と受け渡し

### デッキの文法（任意）

デッキ全体として何の様式なのかを宣言する。**検査できる禁じ手だけを書く。**

```json
"grammar": {
  "id": "answer-led",
  "arc": ["結論", "証拠", "行動"],
  "escalate": ["CARD_ROW", "EQUAL_EMPHASIS"]
}
```

- `arc` は読みの筋。`check_outline.py` が「本文の最初の3枚に先頭の段が現れるか」を見る
- `escalate` は**この文法では軽微で済まない指摘のコード**。`allow` の逆で、重大度を1段上げる。
  「証拠の代わりにカードを並べない」なら `CARD_ROW` と `EQUAL_EMPHASIS` を挙げる
- **検査できない禁じ手をここに書かない。** 「各展示物に含意を1行付ける」は文意の判断で機械にできない。
  それは `pptx-review` の `visual-qa-prompt.md` の観点に置く。書いただけで守られたことにしない

まず `answer-led`（結論先出し）と `evidence-led`（問い→方法→結果→限界）の2つで足りる。
足りなくなってから増やす。

`deck/design-lock.json` に最低限これを書く。

```json
{
  "fonts": ["書体名", "代替書体名"],
  "palette_basis": "この主題の何が色になるのかを一文で",
  "palette": {"bg": "……", "text": "……", "muted": "……", "line": "……",
              "panel": "……", "primary": "……", "accent": "……"},
  "chart_series": ["……", "……", "……", "……"],
  "mode": "doc",
  "min_font_pt": 12
}
```

`palette_basis` が空だと `pptx-create` の骨格が例外で止まる。根拠の無いロックを通さないための検査であり、埋めるための文言をひねり出すのではなく、書けないなら工程1に戻る。

`deck/design-lock.md` には、パレット・書体・型スケール・グリッド・**署名の4条件**・レイアウト名簿と、それぞれを選んだ理由を書く。生成と監査で参照されるのはこちらである。

8枚を超えるデッキでは、`pptx-create` に表紙と本文1枚だけを先に生成・描画させ、利用者に見せて方向を確定してから全ページに進む。ブランド制約が無く方向が定まらないときは、主題から導いた案を2つ（それぞれ表紙＋本文1枚）並べて選んでもらう。3つ以上は出さない。

## 絶対規則

- ロックに書いていない色・書体を後の工程で足さない。足すならロックに戻って書き直す。
- `palette_basis` を空にしない。理由を書けない色は選んでいない。
- 既製の装飾（色帯・飾り線・アイコン入りの丸・角丸カードの反復）を署名として登録しない。
- 既存テンプレがあるときに新しい配色を作らない。実測して写す。
- 型スケールとグリッドは `pptx-create` の骨格の定数と一致させる。片方だけ変えない。
- コントラストの下限（本文 4.5:1、大きな文字 3:1）を割る組み合わせをロックに残さない。

## 出力

`deck/design-lock.json`（機械が読む値）と `deck/design-lock.md`（根拠と署名の定義）、および選んだ理由の要約を返す。高度デザインで自動生成した場合は、候補3案と比較用PPTX、採用した候補とその決め手も返す。
