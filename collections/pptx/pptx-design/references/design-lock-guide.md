# デザインロック — 生成前に決め、生成中は変えない

デザインロックは、全ページが共有する視覚のシステムを1つの文書に固定したものである。生成スクリプトはロックの値だけを参照し、ページごとの逸脱を許さない。変えたくなったらロックを直し、全ページを再生成する。

## 1. 主題から導く

ロックは、**`design-principles.md` の1〜5節で決めた方向を数値に落としたもの**である。先にあちらを読む。ここは記録の書式を定める。

ロックを書く前に、次を1行ずつ答える。

1. このデッキは何についてのものか（具体的な主題を1つ）
2. 誰が、どこで、どの画面で見るか（会議室の投影／自分のPC／印刷）
3. 主題の世界にある素材は何か（道具、図面、現場、用語、時代、素材感）

パレットとシグネチャは 3 から導く。物流なら伝票と路線図、医療なら白と計器、金融なら罫線と数字、といった具合に、主題が持つ言語を使う。外から様式を貼るのがテンプレで、内から導くのが設計である。

**テスト**: このロックに別の主題を流し込んでも成立するなら、まだ設計されていない。

## 2. 既定の外観を知り、そこに落ちない

指示が無いときに生成AIが落ち着く見た目は決まっている。

- 白地に青いヘッダー帯と箇条書き
- 黒地にネオンのグラデーション、巨大な数字、丸角カード3枚
- クリーム地に細身のセリフ、テラコッタの差し色
- 紫から青へのグラデーション背景、ガラス風の半透明パネル

選んで使うなら構わないが、無意識に着地してはいけない。指示があればそれに従う。無ければ上の4つを避ける。

## 3. ロックの雛形（`deck/design-lock.md`）

```markdown
# デザインロック: <デッキ名>

## 主題からの導出
- 主題: 
- 主題の素材: 

## シグネチャ（4欄すべて埋まって初めて署名。空欄が残るなら署名は無い）
- 形（主題のどの素材から取ったか）: 
- 意味（この形が指すもの。1つだけ）: 
- 凡例の一文（初出ページに `motif_legend()` で置く）: 
- 3層の出し方
  - 静かな標識（全ページの定位置）: 
  - 幾何そのもののページ（何ページ目・どういう構造）: 
  - 強く出すページ（3回まで）: 

## パレット（用途つき）
| 役割 | HEX | 用途 |
|---|---|---|
| 背景（`bg`） | （主題から決める） | 全ページの地 |
| 本文（`text`） | （背景と4.5:1以上） | 本文・タイトル |
| 補助文字（`muted`） | （本文より静かな色） | 注記・出典・軸ラベル |
| 罫線（`line`） | （背景に近い色） | 表と図の罫線 |
| 淡い面（`panel`） | （背景と区別できる色） | 図の地。既定では敷かない |
| 主色（`primary`） | （主題から決める） | 章扉の面、図の主系列（視覚重量の60〜70%） |
| 強調（`accent`） | （主色と区別できる色） | 1ページ1か所だけ。主張を支える数字や系列 |

## 書体
- 和文: Yu Gothic（latin と ea の両方に指定）
- 欧文・数字: 同上（分けるなら Arial）
- 太さ: タイトル Bold、本文 Regular

## 型スケール（pt）
- 密度モード: 講演型 / 資料型 のどちらか（骨格の `MODE` と lint の `--mode` に同じ値を渡す）

| 役割 | 講演型 | 資料型 |
|---|---|---|
| 表紙タイトル | 40〜48 | 36〜40 |
| ページタイトル | 28〜32 | 24〜28 |
| 小見出し | 20 | 16 |
| 本文 | 18〜24 | 14〜16 |
| 注記 | 14 | 12 |
| 出典 | — | 10〜11 |
- 行間: 1.3〜1.5
- 箱の高さ = (行数 + 0.5) × サイズ(pt) × 1.4 ÷ 72。半行分の余裕を含める

## グリッド（inch、16:9 = 13.333 × 7.5）
- 余白: 上下左右 0.6（本文の外に出ない）
- 列: 12列、列間 0.25
- タイトル: y 0.6〜2.0（高さ 1.4 = 28pt 2行分＋半行。32pt なら1行に収める）
- 本文開始: y 2.2
- 本文終端: y 6.6
- 出典・ページ番号: y 6.8〜7.1
- 要素間の最小間隔: 0.3

## レイアウト名簿（layout-catalog.md から5〜7種）
- 表紙: 一色面＋左下寄せ
- 主張＋証拠（左図右文）
- 比較（2列）
- 数字（1つだけ）
- 一文（余白の多い宣言）
- 結論・依頼

## 禁止（anti-ai-checklist.md 視覚の項目を再掲）
- タイトル下の飾り線、上下の色帯、側面の縦帯、カード左縁の帯
- 丸角カードの横並びを既定にしない
- 絵文字、グラデーション背景、光彩、ガラス風

## リズム
- 同じレイアウトを3枚以上連続させない
- 同じ塊の形式（例: カード）が本文の40%を超えない
- 濃い面のページ（表紙・章扉・一文）は3回まで
```

## 4. 機械検査用（`deck/design-lock.json`）

pptx-create の生成骨格と pptx-review の lint が同じ `palette` を読む。色は役割名つきで記録し、生成コードへ手で転記しない。`colors` はロゴ色など、palette以外に許可する追加色がある場合だけ使う。

```json
{
  "fonts": ["Yu Gothic"],
  "palette_basis": "地域物流の緑色の通い箱と荷札の橙。主色は経路、強調色は滞留を示す",
  "palette": {
    "bg": "FFFFFF",
    "text": "14211C",
    "muted": "596B63",
    "line": "CFD8D3",
    "panel": "F1F5F2",
    "primary": "1F5C49",
    "accent": "D9822B"
  },
  "min_font_pt": 12
}
```

上の値は「地域物流」という主題に対するJSON構造の例であり、既定パレットではない。`palette_basis` と7つの色は工程1で書いた主題の素材から毎回決め直す。`palette_basis` が空の役割付きpaletteはlintと生成骨格が拒否する。`min_font_pt` は出典を除く全文字の下限で、注記を含む（講演型 14、資料型 12）。本文の下限（講演型 18、資料型 14）は型スケールで守り、描画画像で確認する。

1.2以前の `colors` だけのロックも、先頭7色を `bg`、`text`、`muted`、`line`、`panel`、`primary`、`accent` の順として互換読み込みする。ただし旧 `extract_style.py` の出力は使用頻度順であり役割順ではないため、既存デッキから抽出した古いロックは新しい `extract_style.py` で作り直す。

意図的に残す lint の指摘は `allow` に理由つきで登録する。登録した指摘は判定から外れ、報告には「意図的」として残る。

```json
{
  "allow": [
    {"code": "CARD_ROW", "slide": 4, "reason": "比較対象が実際に3つ"},
    {"code": "FULL_WIDTH_RULE", "reason": "フッター罫線1本。全ページ共通"}
  ]
}
```

## 5. パレットの作り方

- 5〜6色で足りる。背景、本文、補助文字、罫線・面、主色、強調。
- 1色が支配する（視覚重量の60〜70%）。強調色は1ページに1か所。全色を同じ重さで使わない。
- 青を既定にしない。主題に理由があるときだけ青を選ぶ。
- クリーム・ベージュ（F5F5DC、FAF0E6 など）を既定の背景にしない。指定が無ければ白。
- 暗い背景は表紙・章扉・一文のページに限る。全ページ暗くするなら、投影環境で読めるか確認する。
- コントラストは本文で 4.5:1 以上、大きな文字で 3:1 以上。

完成済みのパレット一覧から選ばない。次の順で1色ずつ決める。

1. ブランド指定があれば `primary` にする。無ければ主題の現物、道具、場所、資料から色の根拠を1つ書く
2. `accent` が表す情報を1つ決める（警告、転機、目標値など）。意味が無ければ、鮮やかな色を足さず `primary` の明度差を使う
3. `bg` と `text` を決め、本文のコントラストを確認する
4. `muted`、`line`、`panel` は背景と本文の間から作る。別の色相を増やさない
5. 7役を `palette` に記録し、根拠を `palette_basis` の一文に残す

**不合格**: 「信頼感があるから青」「目立つから赤」のように、主題を別の案件へ置き換えても成立する理由。これは色を選んだのではなく、既定値へ戻っただけである。

## 6. シグネチャは1つ（主題から作る）

このデッキを記憶させる要素を1つ選び、それ以外は静かにする。**既製の見た目から選ぶのではなく、主題の素材から作る。** 上の4欄が埋まらないものは署名ではない。

4条件（`design-principles.md` §5 と同じ）:

1. **主題由来**——物流なら伝票の罫線と番号、医療なら計器の目盛、金融なら台帳の締め線、研究なら取得点と未取得点
2. **1つの形に1つの意味**——「太線＝実測」と決めたら、強調には太線を使わない
3. **初出で凡例**——見たことのない形は、説明が無いと飾りに見える。`motif_legend()` で一行置く
4. **3層で働く**——全ページの静かな標識／幾何そのもののページ1枚／初出の凡例。強く出すのは3回まで

使えるもの: 主題由来の図版言語（路線図、計器、罫線、断面、取得と未取得の格子）、大きな余白と左寄せの見出し、番号の書体、章扉の一色面、写真の裁ち落とし、太い1本の見出し書体。

使わないもの: 色帯、飾り線、光彩、グラデーション、アイコン入りの丸、角丸カードの反復。これらは「シグネチャ」ではなく、生成AIの既定の見た目である。

**判定**: この署名を別の主題のデッキに移せてしまうなら、主題から作られていない。

## 7. テンプレや既存デッキがある場合

利用者のテンプレ（.pptx/.potx）や既存デッキがロックになる。**目分量で読み取らず、実測する。**

```python
import subprocess, sys
subprocess.run([sys.executable, "<skills>/pptx-review/scripts/extract_style.py", "template.pptx",
                "--json-out", "deck/design-lock.json", "--md-out", "deck/design-lock.md"])
```

タイトルの位置・幅・サイズ・太さ・色・揃え、本文のサイズの語彙・左端・行間・箇条書き記号、出典の位置、余白、書体、色、レイアウトの使用回数、そして役割ごとの**複製元**が出る。以降はこの文書を「正」として参照し、記憶や見た目の印象で決めない。

1. 出た値をそのまま使う。新しい色・書体を足さない。足すなら利用者に確認する。
2. 使うレイアウトを名簿に書く。同じレイアウトばかり選ばない。
3. **新しい要素は複製元を複製して作る。** ゼロから `add_textbox` すると PowerPoint の既定書式（Calibri 18pt 黒、行間 1.0）になり、そのページだけ浮く。
4. テンプレ自体に飾り線や色帯があっても、利用者の資産なので消さない。ただし自分で追加しない。
5. 生成後は lint に `--lock deck/design-lock.json` を渡し、統一性の指摘（`*_DRIFT`）が出ていないか確認する。

## 8. ロックの変更手順

ページ単位の例外は作らない。ロックを直し、`build.py` の定数を更新し、全ページを再生成し、再度品質確認する。変更理由は `design-lock.md` の末尾に日付つきで残す。
