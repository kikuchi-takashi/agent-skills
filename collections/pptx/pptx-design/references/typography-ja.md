# 和文タイポグラフィ — 受け手の環境で崩れない書き方

## 1. 書体名しか保存されない

`.pptx` は書体の名前だけを保存し、書体そのものは埋め込まない（埋め込みは例外）。受け手の環境にその書体が無ければ PowerPoint が黙って代替し、幅と行送りが変わって、はみ出しや改行位置のずれが起きる。和文では、代替先が無いと豆腐（□）になる。

したがって、**受け手の環境に確実にある書体を選ぶ**ことが、見た目の安定の最初の条件になる。

## 2. 推奨する和文書体

| 書体 | Windows | macOS | 備考 |
|---|---|---|---|
| 游ゴシック（Yu Gothic） | 8.1 以降 | 10.9 以降 | 両OSにある。ただし太さの構成が異なる（Windows: Light/Regular/Medium/Bold、macOS: Medium/Bold）。Windows の Regular は細く見えるので本文も Medium 相当か太字を検討 |
| メイリオ（Meiryo） | あり | Office 同梱の場合のみ | Windows 中心の配布に向く。行間が広い |
| ヒラギノ角ゴシック（Hiragino Sans） | 無し | あり | macOS 中心の配布に向く |
| BIZ UDPゴシック | 10 以降 | 無し | 読みやすいが Windows 限定 |
| 游明朝（Yu Mincho） | 8.1 以降 | 10.9 以降 | 明朝が要るときの第一候補 |
| Noto Sans JP / 源ノ角ゴシック | 無し | 無し | 受け手が持っている確証があるか、埋め込むときだけ |

**既定は游ゴシック。** 受け手の環境が Windows と分かっていればメイリオでもよい。Noto を無条件に指定しない。

## 3. latin と ea の両方に指定する

DrawingML は文字種ごとに書体を持つ（`a:latin` = 欧文、`a:ea` = 東アジア、`a:cs` = 複合文字）。`a:latin` だけを設定すると、和文はテーマの既定書体（多くは MS Pゴシックや游ゴシックだが環境依存）に落ちる。

python-pptx の `run.font.name` は `a:latin` しか書かない。和文の run には必ず `a:ea` も書く。

```python
from pptx.oxml.ns import qn
from lxml import etree

def set_font(run, latin="Yu Gothic", ea="Yu Gothic"):
    run.font.name = latin
    rpr = run._r.get_or_add_rPr()
    ea_el = rpr.find(qn("a:ea"))
    if ea_el is None:
        ea_el = etree.SubElement(rpr, qn("a:ea"))
        latin_el = rpr.find(qn("a:latin"))
        if latin_el is not None:
            latin_el.addnext(ea_el)   # 順序: latin → ea → cs
    ea_el.set("typeface", ea)
```

図表（chart）の文字は `chart.font.name` でも `a:latin` しか書かれない。図表の `txPr` にも同様に `a:ea` を追加するか、軸ラベルや凡例が和文にならない構成（数値と英字）にする。

生成後に slide XML の `<a:ea typeface=...>` を確認する。pptx-review の lint は、和文を含む run に ea が無いと `NO_EA_FONT` を出す。

## 4. 欧文・数字

- 和文書体で通すのが最も安全。游ゴシックの欧文と数字は十分に読める。
- 数字を目立たせたい（数字ページ、表）なら Arial。等幅性が高く、桁がそろう。
- 欧文書体を混ぜるなら1種類まで。和文1種＋欧文1種が上限。
- 英数字は半角。全角英数字は使わない。
- 数字と単位の間に半角スペースは入れない（「12%」「3か月」）。

## 5. 型スケール（pt）

| 役割 | 講演型 | 資料型 |
|---|---|---|
| 表紙タイトル | 40〜48 | 36〜40 |
| ページタイトル | 28〜32 | 24〜28 |
| 小見出し | 20 | 16 |
| 本文 | 18〜24 | 14〜16 |
| 図表のラベル | 14 | 12 |
| 注記 | 14 | 12 |
| 出典 | — | 10〜11 |

- 本文の下限は講演型 18pt、資料型 14pt。収まらなければ文字を減らす。
- 階層は大きさと太さで作る。書体を増やして作らない。
- 段の差は 1.4〜1.8 倍。24pt の本文に 26pt のタイトルでは階層が見えない。

## 6. 行送りと段落

- 和文の行間は 1.3〜1.5（`line_spacing = 1.4`）。欧文の既定 1.2 では詰まって見える。
- 段落間は行間より広く（`space_after = 6〜10pt`）、行間で段落を分けない。
- 1行の文字数は本文で全角 25〜35 字。幅の広い箱に小さい文字を流すと、視線が戻れない。
- 箇条書きは1項目1行が理想。折り返す項目が1つだけあると、そこだけ間隔が広く見える。全項目を同じ行数にそろえるか、長い項目を削る。
- 禁則（行頭の句読点、行末の始め括弧）は PowerPoint が処理する。python-pptx で手動改行を入れると禁則が壊れるので、`\n` を本文に入れない。
- 両端揃えは使わない。左揃え。中央揃えはタイトルと一文ページだけ。

## 7. 強調

- 太字か色のどちらか一方。両方は使わない。
- 下線は使わない。リンクに見える。
- 和文に斜体は使わない。書体に斜体が無く、機械的に傾けられて崩れる。
- 字間の調整は基本しない。大見出しで −1〜−2% 程度まで。本文で詰めない。

## 8. 記号と句読点

- 句読点は「、」「。」。「，」「．」を混ぜない。
- 括弧は全角「（）」を和文に、半角「()」を英数字の中に。
- 箇条書きの記号は PowerPoint の箇条書き機能で付ける。本文に「・」「•」を直接書かない（二重になる）。
- 「※」は1ページ1つまで。注記は出典行にまとめる。
- 三点リーダーは「…」1文字。「...」を使わない。

## 9. 文字数の予算（箱の幅から）

箱の内側の幅（inch）× 72 ÷ 文字サイズ（pt）で、1行に入る全角文字数の目安が出る。

| 箱の幅 | 14pt | 16pt | 18pt | 24pt | 28pt |
|---|---|---|---|---|---|
| 4.7in（5列） | 24字 | 21字 | 18字 | 14字 | 12字 |
| 7.0in（7列） | 36字 | 31字 | 28字 | 21字 | 18字 |
| 12.1in（全幅） | 62字 | 54字 | 48字 | 36字 | 31字 |

英数字は 0.5 字と数える。この表で行数を見積もり、箱の高さ（行数 × サイズ × 1.4 ÷ 72 inch）を決める。ぎりぎりに設計しない。1行分の余裕を持つ。

## 10. 確認画像と受け手の見え方は違う

視覚確認は pptx-review の `render_preview.py`（Pillow）で行う。この描画は、実行環境にある書体ファイルで文字を描く。

- 指定した書体（游ゴシックなど）が実行環境に無いのが普通である。描画は見つかった和文書体で代替し、無ければ和文を文字幅どおりの灰色バーにする。位置・折り返し・重なり・余白の確認はそれで足りる。
- 字形まで確認したいときは、書体ファイル（.ttf/.otf）を作業ディレクトリに置き、`--font` で渡す。書体ファイルはライセンスを確認したものだけを使い、システムの書体ディレクトリには置かない。
- 実行環境にどの書体があるかは、次で確かめられる。

```python
import sys; sys.path.insert(0, "<skills>/pptx-review/scripts")
import pptx_lint
print(pptx_lint.find_fonts())   # (和文対応の書体, 欧文の書体)。None なら無い
```

- 和文書体の折り返し幅は、全角 1 文字 = サイズ pt でほぼ一定なので、書体が違っても行数の見積もりは大きくずれない。ずれるのは欧文と数字の部分と行送りである。

### 行数は割り算で見積もらない

**全幅 ÷ 行幅 の切り上げは、実際より少なく出る。** 和文は語の途中で折れないので、行末に入りきらなかった分が毎行余る。その余りを割り算は数え落とす（実測: 現実的な和文と幅の組み合わせ 44 通りのうち 5 通りで、実際の折り返しが見積りより1行多かった）。1行ずれると下に積んだものと重なる。

骨格の `wrapped_lines()` と lint の `wrap_count()` は、**1文字ずつ実際に折り返して数える**。両者は同じ定義を持ち、食い違わないことを整合監査が確かめる。

### 禁則処理（JIS X 4051）

行頭に置けない文字（`、。）」・？！` 小書きの仮名、長音符など）と、行末に置けない文字（`（「『【` など）がある。そこに来たときは**直前の文字ごと次の行へ送る（追い出し）**。

- **ぶら下げ（行末に押し込む）を当てにしない。** PowerPoint の既定では働かない
- 追い出しは行が増える側なので、見積りとしても安全側に倒れる
- 文字クラスは `KINSOKU_HEAD` / `KINSOKU_TAIL` として骨格と lint の両方にある。**片方だけ増やさない**
- Aptos（2023年以降の Office の既定欧文書体）は指定しない。古い Office に無く、代替も定まらない。

### 強調色は大きな文字にだけ使う

**強調色は、小さい文字では読めない。** 主色や強調色は地とのコントラストが 3:1 前後になるよう作られており、それは**大きな文字の下限**である。本文・注記・見出し（12〜20pt）に使うと本文の下限 4.5:1 を割る。

| 使ってよい | 使わない |
|---|---|
| 大きな数字（`hero-number`、`metrics` の主役）、章扉の番号 | 本文、注記、出典、図の注記、表の見出し、選択肢の見出し |

強調したいのが小さい文字なら、**色ではなく太字と面で示す**。淡い面に載せて太字にすれば、色を変えずに主役だと分かる。lint の `TEXT_CONTRAST_LOW` がここを拾う——実際に、図の注記と3つの原型（選択肢・差分・目次）で最初の実装が引っかかった。

### 確認が信用できる書体、できない書体

**代替書体の字幅が元と違うと、はみ出し検査そのものが誤る。** 「収まっている」と出たのに受け手では溢れる、あるいはその逆が起きる。指定する書体を、確認の信頼度で分けておく。

| 区分 | 書体 | 扱い |
|---|---|---|
| 確認が信用できる（和文） | 游ゴシック、メイリオ | 本文に使う。全角がサイズ pt ちょうどで、代替が起きても行数がずれない |
| 確認が信用できる（欧文） | Arial、Calibri、Times New Roman、Courier New | 和文と混ぜる欧文はここから1種類だけ |
| 確認が信用できない | Aptos、游明朝の一部ウェイト、環境依存の欧文（Georgia、Trebuchet MS、Impact など） | 見出しや強調で使うなら、箱に1割の余裕を足し、**その要素のはみ出し判定を信用しない**（描画画像を目視する） |

**本文と、幅が効くところ（表のセル、図形の中、箱に詰めた行）には、信用できる区分だけを使う。** 見出しは1行に収まる長さで書くので、代替の幅差が効きにくい。


- 確認画像で「ぎりぎり収まっている」は、受け手の環境では溢れると考える。半行分の余裕を持つ。
- 確認画像で溢れている（赤枠）ものは、受け手の環境でも溢れる可能性が高い。直す。
- 書体の代替が起きたことは、納品時に書く（「游ゴシックを指定。確認は代替書体で実施」または「和文は幅のみ確認」）。

## 11. 納品時に書くこと

- 指定した書体と、受け手の環境に無い場合の見え方
- 確認に使った描画環境と代替の有無
- 書体を埋め込んでいない旨（埋め込みは PowerPoint 側の操作）
