## 追記: 修正ページが浮く問題への対処（2026-09-05）

「修正を依頼すると、そのページだけ既存と揃っていないデザインで返ってくる」への対処。原因は、既存の設計値を読み取る工程がエージェントの目分量に任されていたこと、および新しい要素をゼロから組んで PowerPoint の既定書式（Calibri 18pt 黒、行間 1.0）になっていたこと。

3つ入れた。

1. **`extract_style.py`（新規、標準ライブラリのみ）**。既存デッキから設計値を実測してデザインロック（JSON と Markdown）を書き出す。タイトルの位置・サイズ・太さ・色・揃え、本文のサイズの語彙・左端・行間・箇条書き記号、出典の位置、余白、書体、色、レイアウトの使用回数、そして役割ごとの**複製元**。JSON は lint の `--lock` にそのまま渡せる。
2. **lint の統一性検査**。本文ページ4枚以上のとき、タイトルの位置・幅・サイズ、内容の左端、本文の主たるサイズ、色を多数派と比べ、外れたページに `TITLE_POSITION_DRIFT` / `TITLE_SIZE_DRIFT` / `MARGIN_DRIFT` / `BODY_SIZE_DRIFT` / `PALETTE_DRIFT` を出す。
3. **複製から作る規則**（`pptx-edit/references/match-existing-design.md`）。新しい要素は複製元を `copy.deepcopy` して文言だけ変える。ページを足すときは同じ役割の既存ページを複製する。

### 誤検知を潰した経緯

最初の実装は、揃っているはずの試作デッキに9件の指摘を出した。原因と対処:

| 誤検知 | 原因 | 対処 |
|---|---|---|
| 表紙が本文ページとして比較された | 表紙判定が「塗り図形が無いこと」で、全面塗りの表紙に反応しなかった | 全面塗り（幅・高さとも95%以上）があれば表紙とみなす |
| 数字ページの巨大数字がタイトル扱い | タイトルの代替判定が「最大サイズ」だった | 上部30%の帯にある文字だけを候補にする |
| 2段組みの右列で左端がずれたと判定 | 左端を文字要素の最小値で取っていた | ページの内容全体（図・表・面を含む）の左端で見る |
| 容器の中の文字が左端としてずれた | 容器判定が自分自身も含めていた | 自分より大きい容器に80%以上入るものだけを除外 |
| 型スケールの注記（12pt）が外れ値 | 「そのページだけのサイズ」を全部拾っていた | ページごとの**主たる**本文サイズ（文字数の多いもの）で比べる |
| 色は完全に別の色も指摘 | 新しい色を一律に扱った | 既存の色に**近いが違う**色だけを指摘（距離40以内）。明確に別の色は強調の意図とみなす |

検証: 揃った試作デッキ（8枚）で `*_DRIFT` は0件。あとから手組みで1枚足したデッキでは、その1枚だけに4件。複製元から複製して足したページでは0件。

## 追記: デザイン性の低下を戻す（2026-09-05）

「修正も作成もデザインが平板になった」への対処。原因を調べ、公開スキルでの実践を確認したうえで3つ入れた。

### 診断

| 原因 | 根拠 |
|---|---|
| 制約が3つ（装飾禁止・反復禁止・乖離禁止）になり、積集合が痩せた | 意図的にリズムを付けた検証デッキで、表ページの20pt が `BODY_SIZE_DRIFT` として咎められた。章扉と一文ページは「表紙と誤分類されて」偶然に助かっていた |
| 「必ず直す」と書いた | pptx-edit の指示が、lint の多数派比較を「多数派に寄せろ」という命令に変えていた |
| 見えないものは作らなくなった | 描画が簡易化され影・グラデーション・和文字形が出ない。「合格は描画画像で示す」と組み合わさると、描画器が描けるもの（矩形と文字）に後退する |
| 手置き座標を全面禁止した | 均等配置のヘルパー3つしか無く、非対称・裁ち落としを表現する手段が消えた |
| 肯定的な設計論を書いていなかった | 脱AIチェックリスト3,182字は全節が禁止。主題からの導出は533字だけ |

### 公開スキルでの実践を確認

- レイアウト原型のカタログ: sunbigfly / Akxan は原型11種＋部品9種を個別ファイルで持つ。slides_maker は `skeleton(kind)` が8種、`bento()` が不揃いタイル。Mck は目録＋能力境界の YAML
- 手置き禁止: slides_maker は6か所で "never hand-pick a coordinate"。**制約は同じで、道具の品揃えが違った**。非対称は `columns(weights=(1,2))`、裁ち落としは専用の扱い
- 肯定と禁止の比率: slides_maker の設計原則は76,043字で否定表現140、hands-on-deck は6,834字で7。私の版は3,182字が全部禁止
- 統一と変化の両立: slides_maker は「繰り返すのは静かなシステムであって、いちばん目立つ装飾ではない」とし、単調さを咎める lint を6種持つ（LAYOUT SAMENESS、BOTTOM-STRIP MONOCULTURE ほか）＋形式ファミリー40〜50%上限

### 入れたもの

1. **レイアウト原型の実装**（`engine-notes.md`）。`skeleton(kind)` が10種の領域を返し、対応するレイアウト関数を用意。非対称は `split((1, 2))` の比率、裁ち落としは `bleed()` で表す。手置き禁止は維持し、道具を増やした
2. **肯定的な設計論**（`design-principles.md`、新規）。主題からの導出、不均等な投資（120%/80%）、リズムの3拍、静かな層とうるさい層、シグネチャ、余白、型の選び方、引き算。肯定:禁止が 2.7:1 になった
3. **lint の層分け**。`BODY_SIZE_DRIFT` は型スケールから3pt以内の外れだけに限定（密度の設計判断は残す）。`PALETTE_DRIFT` は文字色だけを見る（淡い面色は設計判断）。形式ファミリーを分類して `FORM_FAMILY_MONOTONE` を追加し、レポートに内訳を出す

### 検証

| デッキ | 結果 |
|---|---|
| 原型を使い分けた9枚（表紙・図表・数字・非対称・一文・章扉・比較・手順・結論） | 0 errors 0 warnings。内訳「文章2 / 図表1 / 大きな数字1 / 多段1 / 箇条書き1」 |
| 文章ばかりの6枚 | `FORM_FAMILY_MONOTONE` と `LAYOUT_MONOTONE` |
| 1枚だけ手組みで足したデッキ | その1枚に4件の `*_DRIFT` |
| 複製元から複製して足したページ | 0件 |

道具側の不具合も2つ見つけて直した。章扉の番号枠が84ptに足りず溢れていた点と、淡い面色（F4F4F2 対 FFFFFF）を色の乖離として誤検出していた点。

## 追記: 改善ループ3周（2026-09-05）

### 1周目 — 壊れやすい入力で試す

テンプレのプレースホルダ継承、グループ図形、3枚だけ、1枚だけ、0枚、4:3 のデッキを作って3本のスクリプトに通した。落ちはしなかったが、判断の誤りが3件あった。

| 見つけたもの | 直したこと |
|---|---|
| テーマ由来の塗り（`style` の `fillRef`）を「塗られていない」と判定。python-pptx や PowerPoint の既定図形はこの形なので、実デッキのカードが検出できていなかった | `has_fill` が style の fillRef も見る |
| 1枚目を無条件に表紙として検査から外していた。本文から始まるデッキで1枚が検査対象から漏れる | 表紙判定を2段階にし、全面塗り・上部帯にタイトルが無い・タイトルが多数派より25%以上大きい、のいずれかで判定 |

### 2周目 — 検査の精度を測る

「出るべき指摘が出るか」「出てはいけない指摘が出ないか」をケースで測る仕組みを作った（`scripts/eval-checks.py`、23件）。初回は19件すべて通ったので、判断の難しい条件を6件足したところ1件落ちた。

|---|---|
| 多数派が3対3で割れているとき、片方を任意に選んで残り3枚を咎めていた | 「3枚以上かつ過半数」を満たすときだけ多数派と認める |

通るようになったケース: テンプレ継承＋手置き1枚、4:3で1枚ずれる、多数派が既定値ではないデッキ、本文ちょうど4枚＋ずれ1枚、多数派が割れている、グループ内のタイトル。

### 3周目 — 文書と実装の整合を監査する

文書に書いた数値・原型名・フラグが実装と食い違っていないかを機械的に確かめる仕組みを作った（`scripts/audit-consistency.py`）。2件の食い違いが見つかった。

監査が見る対象: グリッド定数、型スケール、数値ガードレール、文書中のコマンドフラグ、監査基準と lint のコードの双方向、レイアウト原型の実装、抽出したロックが lint に通るか。
